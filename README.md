# OctetoWeb

Website for **OctetoHaret**, FIRST Tech Challenge team **#25474** — IPLT „Spiru
Haret", Chișinău, Republic of Moldova.

Most of this site's traffic is a judge scanning a QR code off a printed shirt on
congested venue wifi. Speed and the RO / EN language system are the two things
that matter most. Read [CLAUDE.md](CLAUDE.md) before contributing — it is the
spec, and it wins over anything here.

---

## Stack

| Layer | Choice |
|---|---|
| Runtime / package manager | Bun |
| Framework | React 19 + Vite 8 + TypeScript (`strict`) |
| Routing / full-stack | TanStack Start (file-based routing) |

| Components | shadcn/ui (`radix-nova`) |

| ORM | Drizzle + drizzle-kit |

| Validation | Zod |
| Deploy | Vercel (via Nitro) |

## Setup

Requires [Bun](https://bun.com). Never use npm, yarn or pnpm — `bun.lock` is
committed and is the lockfile of record.

```bash
bun install
```

Copy the environment template and fill it in:

```bash
cp .env.example .env
```

You need, at minimum, a `DATABASE_URL` from [Neon](https://neon.tech) before
anything touches the database. `SESSION_SECRET` can be generated with:

```bash
openssl rand -base64 32
```

Start the dev server on http://localhost:3000:

```bash
bun run dev
```

## Scripts

| Command | Does |
|---|---|
| `bun run dev` | Dev server on port 3000 |
| `bun run build` | Production build to `.output/` |
| `bun run preview` | Serve the production build locally |
| `bun run start` | Run the built server (`node .output/server/index.mjs`) |
| `bun run typecheck` | `tsc --noEmit` |
| `bun test` | Run the test suite (Bun's built-in runner) |
| `bun run generate-routes` | Regenerate `src/routeTree.gen.ts` by hand |
| `bun run db:generate` | Generate a SQL migration from schema changes |
| `bun run db:migrate` | Apply pending migrations |
| `bun run db:push` | Push schema straight to the database (dev only) |
| `bun run db:studio` | Open Drizzle Studio |
| `bun run db:seed` | Insert placeholder content — safe to re-run |

`db:generate` works without a database so migrations can be generated in CI.

### Working without Neon

Until a Neon project exists, the app runs against **PGlite** — an in-process
Postgres kept in `.pglite/` (gitignored). It is picked automatically whenever
`DATABASE_URL` is unset, and refused outright in production.

```bash
bun run db:local   # apply migrations to a fresh local database
bun run db:seed    # add placeholder content — safe to re-run
```

PGlite allows a single writer, so **stop the dev server before running
`db:local` or `db:seed`**, then start it again.

Once you have a Neon connection string, put it in `.env` and nothing else
changes: `DATABASE_URL` being present switches the driver, and `db:migrate`
applies the same committed migrations.

`src/routeTree.gen.ts` is generated by the Vite plugin on dev and build. It is
gitignored — do not edit it or commit it.

## Deployment — Vercel

**There is no Vercel preset or adapter.** The TanStack Start hosting docs route
Vercel through Nitro, and the TanStack CLI's `--deployment` flag has no `vercel`
value. What makes the Vercel build work is the `nitro()` plugin already wired
into `vite.config.ts`; Nitro detects the Vercel build environment and emits the
right output on its own. Do not add a `target: 'vercel'` option — that belonged
to the old `app.config.ts` era and no longer exists.

To deploy: import the repository on Vercel, set the environment variables from
`.env.example` in the project settings, and it builds with `vite build`.

Set `GOOGLE_REDIRECT_URI` to the deployed origin and add the same URL to the
Authorised redirect URIs in the Google Cloud console, or admin sign-in fails.

## Notes for contributors

- **`ALLOWED_ADMIN_EMAILS`, `SESSION_SECRET` and `DATABASE_URL` are server-side
  only.** Never give a secret a `VITE_` prefix — that inlines it into the client
  bundle. Only `VITE_SITE_URL` is intentionally public.
- `verbatimModuleSyntax` is switched **off** in `tsconfig.json` on purpose. The
  TanStack Start docs warn it can leak server bundles into the client bundle.
  Leave it off.
- Members are 14–18. `photoConsent` and `fullNamePublic` both default to
  `false`, EXIF is stripped from every upload, and there is no third-party
  analytics. See CLAUDE.md §8 before adding anything that collects data.
- Bilingual RO / EN is a database-level concern (`…Ro` / `…En` column pairs),
  not a render-time translation. Build both locales from the start.
- **Every public route belongs under `src/routes/$locale/`.** An unprefixed
  content route is invisible to the language system: it gets no `hreflang`, and
  the switcher can only send readers to the locale home rather than to the
  equivalent page. Only `/q/`, `/admin/` and `/styleguide` sit outside.
- **Render bilingual database fields with `<LocalizedText>`**, never by reading
  `…En ?? …Ro` inline. The component is what guarantees the "available in
  Romanian only" note appears and that an empty block never renders.
- **A route guard is not an authorization boundary.** `/admin/_authed`'s
  `beforeLoad` only stops someone loading a screen that would fail anyway. A
  server function is an endpoint reachable on its own, so every one that
  touches admin data must use `adminMiddleware` from
  `@/server/auth/middleware`.
- **Do not re-export `./middleware` or `./session` from `@/server/auth`.** That
  barrel is imported by route files, which are part of the client build;
  re-exporting server-only modules through it fails import protection. Import
  them directly from server-side code instead.
- **Apply the §8 consent rules in the server function, not in the component.**
  A loader's return value is serialised into the HTML for hydration, so
  anything it returns is readable in view-source whether it renders or not.
  `src/server/team.ts` strips `name`, `photoConsent` and `fullNamePublic` and
  returns a `displayName` plus a photo the site is allowed to show — so a
  withheld photograph's URL never leaves the server.
- **Redirects are 302, never 301** for anything language-related. A permanent
  redirect is cached indefinitely and would pin a reader to one language.

## Known scaffold gaps

Things deliberately left undone, so nobody assumes they were forgotten:

1. **The brand hexes in `src/styles/theme.css` are estimates** sampled from
   Instagram screenshots. Replace them from the logo SVG before launch
   (CLAUDE.md §15.1). `/styleguide` recomputes every contrast ratio from these
   values, and `contrast.test.ts` fails if a pairing stops clearing AA — so
   swapping them tells you immediately what broke.
2. **Archivo loads on the weight axis only.** The width axis §7.6 mentions
   costs 106 KB more (171 KB vs 65 KB for latin + latin-ext). Switch the
   import in `app.css` to `archivo/wdth.css` to enable it.
3. **Font swap is an unmeasured CLS risk.** The three families load with
   `font-display: swap` and no fallback metric overrides, so text reflows when
   they arrive. The fix is a `@font-face` fallback with `size-adjust` /
   `ascent-override` tuned to each family. Phase 7 measures CLS; do it there
   rather than guessing the numbers now.
4. **A Romanian reader downloads ~145 KB of fonts** (latin + latin-ext across
   three families); an English reader ~86 KB. This is the largest single
   payload on a cold visit — see §12 before adding a fourth family.
5. **No public routes or auth.** `/` renders a blank shell. Locale-prefixed
   routing, the QR resolver and admin are all still to build. `/styleguide` is
   an internal review page: it is `noindex`, is not locale-prefixed, and
   should be gated or removed before launch.
5. **Provisional dates in the seed.** CLAUDE.md gives the month the team was
   founded and the year of each award, but `foundedDate` and `eventDate` are
   NOT NULL. Those values are parked in the `PROVISIONAL` block at the top of
   `src/db/seed.ts` and must be corrected before launch — a wrong award date
   on a judge-facing page is worse than a missing one.
6. **`qrCode.printedOn` is modelled as a date**, meaning "when this code went
   to print". CLAUDE.md §5 does not give its type and it could equally mean
   the physical surface — but `label` already covers that, so a date adds
   information rather than duplicating it. Confirm with the team.
