# Vault enrichment

`graphify-out/obsidian/` is generated by graphify. Out of the box its ~1,000
symbol notes carry frontmatter and a Connections list but **no context** —
nothing about what the symbol is or why it exists.

These scripts add a `## Context` section to every node, derived from source:
the doc comment above the declaration, the signature, the package version, or
the relevant `CLAUDE.md` section. **Nothing is invented** — where a symbol has
no comment, the note falls back to its file's header and says so.

## Running them

Order matters; each pass fixes what the previous left generic.

```bash
python scripts/vault/1_enrich_nodes.py
python scripts/vault/2_enrich_spec_and_config.py
python scripts/vault/3_enrich_docs_and_rationale.py
python scripts/vault/4_port_handbook.py
```

They are **idempotent** — blocks are delimited by `<!-- context:begin -->` /
`<!-- context:end -->` and replaced in place, so re-running is safe.

> [!important] Re-run these after any `graphify update`
> `graphify-out/` is **gitignored** — it is regenerated output. Rebuilding it
> drops every Context block and every handbook note. That is the whole reason
> these scripts are committed rather than being a one-off, and why the
> handbook itself lives in `docs/handbook/` where git keeps it.

## What each pass does

| Pass | Covers |
|---|---|
| 1 | Every node with a `source_file` — TS/TSX declarations, package deps and scripts, migrations, images, communities, and file-level notes |
| 2 | `CLAUDE.md` concept nodes (which carry no line number, so they are mapped to their section explicitly) and JSON config keys |
| 3 | Nodes sourced from other markdown files, and `rationale` nodes — decisions recorded in code comments |
| 4 | Copies `docs/handbook/` into the vault as `_CONTEXT_*` notes |

Notes whose own `note_type` is `context` or `index` are skipped: they are
hand-written context already, and a generated block would only get in the way.

## Two traps worth knowing

**`re.sub` replacement strings.** Extracted code contains regex literals like
`/^\/q\/?/`. Passing that as a replacement string makes Python read the
backslashes as group references and raise `bad escape`. All three passes use a
`lambda` replacement instead. This only shows up on a *re-run*, when the
substitution path is taken rather than the insert path.

**Signature extraction.** Counting braces alongside parens makes
`): Promise<T> {` net to zero, so the scan never terminates and swallows the
function body. Only parens and brackets are counted, and a chained builder
(`z` then `.string()`) is followed so `const x = z` is not reported as the
whole declaration.
